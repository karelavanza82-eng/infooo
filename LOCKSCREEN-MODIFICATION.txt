HOISLY - LOCK SCREEN WAKE FIX

What changed:
- Keeps the Hoisly decorative lock-screen overlay and its large live clock/date.
- The existing Enable Hoisly Lock Screen switch remains under Settings > Gestures and Home > Home Behavior (the exact navigation label may vary by app language/version).
- When ACTION_SCREEN_OFF is received while the launcher is started and the feature is enabled, MainActivity calls setShowWhenLocked(true) before the display wakes.
- When the launcher resumes after the display was off, the Compose lock-screen overlay is shown immediately without an artificial timer delay.
- Swiping up asks Android KeyguardManager to dismiss the system keyguard. On a swipe-only device this should dismiss without credentials; PIN, pattern, password, or biometric security remains controlled by Android.
- Disabling the switch prevents the Hoisly overlay from being shown on the next wake.

Important Android limitation:
This remains a decorative launcher lock screen, not a replacement for Android/HiOS Keyguard. Android/OEM lifecycle and background-launch policies can still affect whether and exactly when the activity is shown. No artificial delay is added, but literal 0 ms presentation cannot be guaranteed. On devices with secure credentials, Hoisly cannot bypass them.

Build:
Use the included GitHub Actions workflows or run ./gradlew :app:assembleDebug in an environment with the configured Android SDK and Gradle distribution available.

Validation note:
The source changes were inspected and the ZIP archive integrity was checked. A Gradle build was not run in this environment, so run GitHub Actions and verify compilation before installing the APK.


---- PATTERN LOCK SCREEN (LockDroid-style) ----

The previous swipe-only lock screen (ui/lockscreen/HoislyLockScreen.kt) was removed and replaced by:
- ui/lockscreen/PatternLockScreen.kt  - new lock screen: clock, battery, notification cards, flashlight/camera and a 3x3 pattern pad.
- ui/lockscreen/PatternPad.kt         - Compose port of LockDroid's swipe lock view (dots, line following the finger, normal/warning/valid colours).
- ui/lockscreen/PatternLogic.kt       - hit testing, pattern validation, salted SHA-256 hashing, wrong-attempt lockout (5 tries -> 30 s).
- ui/settings/PatternSetupDialog.kt   - draw the pattern twice to set it; Lock Screen settings has Set / Change / Remove Pattern.

Behaviour:
- With a pattern set, the pad must be drawn correctly before Android's keyguard dismiss is requested. Only a salted hash is stored (PanelPreferences.lockPattern).
- Without a pattern, swipe up unlocks exactly as before.
- This is still an app-level screen above Android's keyguard: it does not replace Android's PIN/pattern/biometrics, and the system keyguard is still dismissed through KeyguardManager.

LockDroid (iOS/Theos tweak, Objective-C) cannot run on Android, so its swipe-lock view was ported, not copied.
Not built here: no Android SDK in the environment. Run ./gradlew :app:testDebugUnitTest :app:assembleDebug (or GitHub Actions) to verify.
